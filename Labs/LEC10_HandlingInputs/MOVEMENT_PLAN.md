# 방향키 캐릭터 이동 제작 계획

## 목표

`pico2d`를 사용해 소년 캐릭터를 방향키로 이동시키고, 이동 및 대기 상태에 맞는 스프라이트 애니메이션을 재생한다. 배경은 `TUK_GROUND.png`, 캐릭터 스프라이트 시트는 `animation_sheet.png`를 사용한다.

## 확정 요구사항

- 방향키 위, 아래, 왼쪽, 오른쪽으로 소년을 이동한다.
- 입력이 없을 때는 IDLE 애니메이션을 재생한다.
- 이동 중에는 해당 방향의 이동 애니메이션을 재생한다.
- 위아래로 이동할 때는 기존 좌우 바라보는 방향을 유지한다.
- 캐릭터가 화면 경계에 닿으면 경계를 넘어가지 않는다.
- 배경으로 `TUK_GROUND.png`, 캐릭터 스프라이트 시트로 `animation_sheet.png`를 사용한다.
- 작업은 새 브랜치에서 진행하고, 완료 후 `main` 브랜치에 병합한다.
- 구현 과정에서 의미 있는 커밋을 최소 15개 만든다. 모든 커밋 메시지는 한글로 작성한다.

## 구현 기준

- 현재 입력 실습 코드에서 사용 중인 `pico2d`와 이벤트 처리 방식을 따른다.
- 화면 좌표와 SDL 입력 좌표의 방향 차이를 고려해 위/아래 이동이 의도한 방향과 일치하는지 확인한다.
- 키를 누르고 있는 동안 이동하고, 키를 놓으면 이동을 멈춘다. 여러 방향키 입력이 겹치는 경우에도 이동 상태와 애니메이션 상태가 일관되도록 처리한다.
- 좌우 이동 시 바라보는 방향을 갱신한다. 위아래 이동 및 IDLE 상태에서는 마지막 좌우 바라보는 방향을 보존한다.
- 스프라이트 시트의 행, 프레임 순서, IDLE 프레임은 실제 `animation_sheet.png`를 확인한 뒤 결정한다. 확인되지 않은 좌표나 프레임 수를 가정하지 않는다.
- 이동 속도와 애니메이션 프레임 갱신은 실행 프레임률에 지나치게 좌우되지 않도록 관리한다.
- 캐릭터의 기준점이 화면 밖으로 벗어나지 않도록 이미지 크기를 고려해 위치를 제한한다.

## 단계별 커밋 계획

각 단계에서 변경 범위를 작게 유지하고, 가능한 경우 실행 또는 동작을 확인한 뒤 커밋한다. 아래 커밋 메시지는 모두 한글이며, 실제 작업 내용과 일치하도록 작성한다.

| 순서 | 작업 내용 | 커밋 메시지 예시 |
|---:|---|---|
| 1 | 새 기능 브랜치 생성 및 기본 실행 구조 확인 | `기능 브랜치에서 이동 실습 준비` |
| 2 | 캔버스 크기와 배경 이미지 로드 정리 | `TUK 배경과 화면 크기 설정` |
| 3 | 소년 스프라이트 시트 로드 및 표시 확인 | `소년 스프라이트 시트 표시` |
| 4 | 시트의 방향별 행과 프레임 배치 조사 | `방향별 스프라이트 프레임 확인` |
| 5 | IDLE 및 이동 애니메이션 데이터 정의 | `대기와 이동 애니메이션 정보 정의` |
| 6 | 캐릭터 위치와 이동 상태 관리 | `캐릭터 위치와 이동 상태 추가` |
| 7 | 방향키 누름 이벤트 처리 | `방향키 누름 입력 처리` |
| 8 | 방향키 해제 이벤트 처리 및 정지 상태 전환 | `방향키 해제와 정지 상태 처리` |
| 9 | 좌우 이동 및 바라보는 방향 갱신 | `좌우 이동과 바라보는 방향 구현` |
| 10 | 상하 이동 및 좌우 방향 보존 | `상하 이동 중 바라보는 방향 유지` |
| 11 | 동시 입력 및 대각 이동 규칙 적용 | `여러 방향키 입력 처리` |
| 12 | 이동 방향별 애니메이션 재생 | `이동 방향별 애니메이션 적용` |
| 13 | IDLE 애니메이션과 마지막 방향 연결 | `대기 애니메이션과 방향 연결` |
| 14 | 화면 경계에서 캐릭터 위치 제한 | `화면 경계 이동 제한` |
| 15 | 이동 속도 및 시간 기반 프레임 갱신 조정 | `이동과 애니메이션 시간 갱신 조정` |
| 16 | 경계, 입력 조합, 상태 전환 최종 확인 후 `main` 병합 | `방향키 이동 기능 최종 검증 및 병합` |

## 작업 및 병합 절차

1. 현재 작업 내용을 보존한 상태로 `main`에서 새 기능 브랜치를 만든다. 예: `feature/character-directional-movement`.
2. 위 계획에 따라 구현하고, 각 단계의 변경을 검증한 뒤 한글 메시지로 커밋한다. 문서 작성 커밋은 구현 커밋 15개에 포함하지 않는다.
3. 최소 15개의 구현 커밋이 모두 한글 메시지인지 확인한다.
4. 최종 검증을 마친 뒤 `main`으로 이동해 기능 브랜치를 병합한다.
5. 병합 후 실행 및 Git 상태를 확인하고, 기능 브랜치는 필요에 따라 정리한다.

## 검증 기준

- 실행 시 `TUK_GROUND.png`가 배경으로 표시되고, `animation_sheet.png`의 소년이 정상적으로 그려진다.
- 방향키 네 개 각각으로 캐릭터가 올바른 방향으로 이동한다.
- 키를 누르는 동안 이동 애니메이션이 재생되고, 모든 이동 입력이 해제되면 IDLE 애니메이션으로 전환된다.
- 상하 이동 후에도 기존 좌우 바라보는 방향이 유지되며, IDLE 상태에서도 방향이 갑자기 바뀌지 않는다.
- 화면 네 경계에서 캐릭터가 화면 밖으로 나가지 않는다.
- 여러 방향키를 조합하거나 누른 키를 해제할 때 이동 및 애니메이션 상태가 꼬이지 않는다.
- 기능 브랜치에 구현 커밋이 최소 15개 있고, 모든 커밋 메시지가 한글이며, 완료 후 `main`에 병합되어 있다.
